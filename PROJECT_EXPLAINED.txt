1) What this project is
-----------------------
Project name: live-odds-pulse

It is a frontend web app built with Vue 3.
The app shows a list of sports matches and betting odds.
Odds change automatically every ~1.4 seconds (mocked stream).
Users can:
- filter by sport
- filter by league
- search teams by text
- save favorite matches

The project is intentionally small, but built in a "professional" style:
- reusable components
- centralized state store (Pinia)
- unit + integration tests
- GitHub Actions CI

5) App boot process (what happens from zero)
--------------------------------------------
When user opens the app URL:

Step 1.
Browser downloads index.html.

Step 2.
index.html loads src/main.js.

Step 3.
main.js:
- imports createApp from Vue
- imports createPinia
- imports App.vue and styles.css
- creates Vue app
- attaches Pinia to app
- mounts app on #app

Step 4.
App.vue is rendered.

Step 5.
In App.vue onMounted hook:
- store.init() loads initial match data + favorites from localStorage
- store.connect() starts mocked live updates

Step 6.
UI shows:
- header with stream status
- filter bar
- list of match cards

Step 7.
Every ~1.4 seconds stream updates one random odd.
Store updates state.
Vue re-renders only changed parts.


6) Data seed file
-----------------
File: src/data/seedMatches.js

Exports: seedMatches (array of match objects).
Each object has:
- id: unique identifier
- sport: Football/Basketball/Tennis
- league: league name
- home: home team/player
- away: away team/player
- startTime: ISO date string
- odds object:
  - home odd
  - draw odd (0 for sports where draw not used)
  - away odd

This is the base data loaded when app starts.


7) Mock stream service (fake real-time)
---------------------------------------
File: src/services/mockOddsStream.js

Purpose:
Simulate a WebSocket/live feed without backend.

Important constants:
- marketsBySport:
  - Football: home/draw/away
  - Basketball: home/away
  - Tennis: home/away
- MIN_ODD = 1.01
- MAX_ODD = 15

Function: nextOdd(currentValue)
- random direction (+ or -)
- random step between 0.01 and 0.09
- applies change
- clamps result to min/max
- rounds to 2 decimals

Function: startMockOddsStream({ matches, onUpdate, intervalMs, onDisconnect })
- starts setInterval with intervalMs (default 1400ms)
- each tick:
  1. if no matches, return
  2. choose random match
  3. choose random market allowed for that sport
  4. generate new odd value using nextOdd()
  5. call onUpdate({ matchId, market, value })
- returns stop function:
  - clearInterval
  - call onDisconnect if provided

This design mimics a real subscription connection with start/stop.


8) Pinia store (central brain)
------------------------------
File: src/stores/matches.js
Store name: matches

Why this is important:
Instead of each component managing its own copy of data, one store manages all shared state.
This improves consistency and maintainability.

8.1) Helper constants and functions
-----------------------------------
A) FAVORITES_STORAGE_KEY
String key in localStorage: live-odds-pulse:favorites

B) resetMatch(match)
Creates runtime version of a match with extra fields:
- cloned odds object
- movement object (home/draw/away all "same")
- isFavorite false

C) safeParseFavorites()
- reads localStorage
- parses JSON
- returns Set of IDs
- if parsing fails, returns empty Set

D) safeSaveFavorites(matches)
- gets all isFavorite=true IDs
- saves JSON array to localStorage
- wrapped in try/catch to avoid crashes in restricted environments

8.2) State
----------
- matches: array of all runtime matches
- filters:
  - sport (default All)
  - league (default All)
  - search (default empty)
- isConnected: stream on/off
- lastUpdatedAt: ISO timestamp of last odds update
- stopStream: function returned from mock stream to stop interval

8.3) Getters
------------
A) sports
Returns ["All", ...unique sports from matches]

B) leagues
- if sport filter is All: all leagues
- else: only leagues for selected sport
Returns ["All", ...unique leagues]

C) filteredMatches
Applies all active filters:
1. sport filter
2. league filter
3. text search on "home away"
Then sorts:
- favorites first
- then by startTime ascending

8.4) Actions
------------
A) init()
- reads favorites from localStorage
- loads seedMatches
- transforms each with resetMatch()
- sets isFavorite true when ID is in favorites set
- resets lastUpdatedAt to null

B) connect()
- if already connected (stopStream exists), do nothing
- set isConnected true
- start stream with startMockOddsStream()
- on updates, call applyOddsUpdate
- on disconnect callback, set isConnected false

C) disconnect()
- if stopStream exists, call it and clear it
- set isConnected false

D) setFilters(partialFilters)
- merges new partial values into filters
- validates league against current available leagues
  (if invalid after sport change, resets league to All)

E) toggleFavorite(matchId)
- find match by ID
- flip isFavorite boolean
- persist favorites to localStorage

F) applyOddsUpdate({ matchId, market, value })
- find match by ID
- verify market exists in match.odds
- compare previous vs new value
- set movement:
  - up if increased
  - down if decreased
  - same if equal
- save new odd value
- update lastUpdatedAt timestamp

Template sections:

   - last updated text
   - pause/resume button
2. FilterBar:
   - passes sports/leagues/filters as props
   - receives update-filters event and calls store.setFilters
3. LiveBoard:
   - passes filteredMatches
   - receives toggle-favorite event and calls store.toggleFavorite

17) Real user interaction flow examples
---------------------------------------
Example A: User filters by sport
1. User chooses "Football" in FilterBar.
2. FilterBar emits update-filters event.
3. App forwards to store.setFilters().
4. store.filters.sport updates.
5. leagues getter recalculates football-only leagues.
6. filteredMatches getter recalculates visible list.
7. LiveBoard re-renders with football matches only.

Example B: User favorites a match
1. User clicks Save button on card.
2. LiveMatchCard emits toggle-favorite(matchId).
3. LiveBoard passes event up to App.
4. App calls store.toggleFavorite(matchId).
5. match.isFavorite flips true/false.
6. safeSaveFavorites writes IDs to localStorage.
7. filteredMatches resorts so favorites appear first.
8. UI updates button label to Saved.

Example C: Live odd update arrives
1. setInterval tick runs in mock stream.
2. random match + market selected.
3. new odd generated.
4. store.applyOddsUpdate called.
5. previous odd compared with next odd.
6. movement direction set (up/down/same).
7. odd value replaced.
8. lastUpdatedAt timestamp refreshed.
9. only affected UI values re-render.

20) Common beginner confusion points
------------------------------------
Q: Why use Pinia for a small app?
A: Because this mirrors real production architecture and scales better.

Q: Why "draw" exists but is 0 for tennis/basketball?
A: Simplifies model consistency while UI hides draw when value <= 0.

Q: Why use try/catch around localStorage?
A: Some environments block storage; app should not crash.

Q: Why mock stream in tests?
A: Random intervals make tests flaky. Mocking gives deterministic behavior.
